# ML-ядро (Python)

Ядро проекта: превращает PGN в набор измеримых ошибок и сквозных паттернов.

```
PGN ──▶ разбор ходов и часов ──▶ оценки движка по позициям ──▶ cp-loss/точность/фазы
                                                              │
                                    ошибки + «надлом» ◀────────┘
                                            │
                                    сквозные паттерны (по многим партиям)
```

## Что уже умеет

- Разбор одиночных и мультипартийных PGN (включая часы `%clk` из Lichess/Chess.com).
- Оценка позиций через Stockfish по UCI; при отсутствии движка — эвристический fallback
  (материал + пара слонов), чтобы пайплайн оставался рабочим.
- cp-loss на каждый ход, точность по формуле Lichess, классификация фаз (дебют/миттельшпиль/эндшпиль).
- Ошибки: неточность ≥ 50 cp, ошибка ≥ 100 cp, зевок ≥ 200 cp (настраивается).
- Детекторы сквозных паттернов (см. таблицу ниже).
- Гипотеза «надлома» (breaking point) — сдвиг средних по окну ходов.
- HTTP API: `GET /health`, `POST /api/v1/analyze`, Swagger на `/docs`.

## Запуск

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m uvicorn chess_analyzer.main:app --reload --port 8000
```

Конфигурация — переменные окружения или `.env` (шаблон в `.env.example`).
Ключевые: `STOCKFISH_PATH`, `STOCKFISH_DEPTH`, `MAX_DEPTH`, `MAX_GAMES_PER_REQUEST`, пороги ошибок.
`MAX_DEPTH` (по умолчанию 10) — жёсткий потолок: глубина из запроса зажимается в него,
чтобы на слабом сервере разбор партии не превращался в минуты.

Без Stockfish сервис тоже работает и честно сообщает об этом в `/health`:
`engine.name = "heuristic"`, `note` с пояснением.

### Stockfish

```powershell
.\scripts\fetch_stockfish.ps1     # кладёт бинарник в tools/ (папка в .gitignore)
```

Затем в `.env`:

```dotenv
STOCKFISH_PATH=D:\projects\ChessPatternAnalyzer\ml\tools\stockfish\...\stockfish-windows-x86-64-universal.exe
STOCKFISH_DEPTH=10
```

Лицензия Stockfish — GPLv3: бинарник не коммитим, на сервере запускаем как отдельный процесс.

## API

```http
POST /api/v1/analyze
Content-Type: application/json

{
  "pgn": "...",
  "player": "Duke Karl",
  "depth": 10,
  "max_games": 10
}
```

`player` — ник как в PGN либо `white`/`black`. Анализируются только ходы этого игрока,
поэтому сквозные паттерны считаются «от первого лица». Ответ: `meta`, `games[]`, `patterns[]`,
`breaking_point` (сводка).

Ошибки домена возвращаются как `422` с понятным `detail` (пустой PGN, игрок не найден).

## Детекторы паттернов

| Код | Что ловит | Порог (по умолчанию) |
|---|---|---|
| `conversion_collapse` | Был перевес ≥ +2.0, партия не выиграна | ≥ 2 партий с перевесом, доля упущенных |
| `time_trouble` | При остатке ≤ 30 с ошибки дороже, чем при ≥ 60 с | ≥ 8 ходов в каждом ведре, рост ≥ 1.5× |
| `opening_leak` | Повторяющиеся потери в дебюте | средняя потеря ≥ 40 cp, ошибки в ≥ 2 партиях |
| `phase_gap` | Одна фаза проседает сильнее остальных | ≥ 8 ходов в фазе, просадка ≥ 1.4× |

Каждый паттерн возвращает `severity` (насколько сильно), `confidence` (насколько данных хватает)
и `evidence` — конкретные партии и ходы, чтобы вывод можно было проверить, а не принять на веру.

**Сквозной паттерн требует нескольких партий.** Одна партия даёт метрики и «надлом», но не паттерн.

## Структура пакета

```
src/chess_analyzer/
├── main.py            # фабрика FastAPI-приложения
├── config.py          # настройки из окружения
├── service.py         # оркестрация: PGN → анализ → паттерны
├── api/               # маршруты, схемы pydantic, маппинг домена в JSON
├── domain/            # модели предметной области + определение фаз
├── engine/            # контракт Evaluator, Stockfish (UCI), эвристика, фабрика
├── ingest/            # разбор PGN
├── analysis/          # cp-loss, точность, метрики по фазам
└── patterns/          # детекторы паттернов и «надлом»
```

Домен не зависит от FastAPI и Stockfish — поэтому детекторы тестируются на синтетических
партиях без движка.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Покрыто: разбор PGN и часов, классификация фаз, расчёт cp-loss/точности на скриптованном
движке, все детекторы (позитивные и негативные сценарии), API целиком через `TestClient`.

## Известные ограничения M0

- Анализ синхронный, один процесс, движок сериализуется блокировкой — нет очереди и воркеров.
- Нет БД и кэша: повторный запрос пересчитывает всё заново.
- Нет Maia: «человечность» ошибки не моделируется, только объективная потеря.
- «Надлом» — эвристика на скользящем окне, а не обученная модель.
- Без Stockfish качество паттернов резко падает (виден только материал).

Всё перечисленное закрывается вехами M1–M4 в [../Roadmap.md](../Roadmap.md).

## Если что-то пошло не так

- **`pip` зависает на «Installing build dependencies».** Поставьте сборщик в venv и повторите
  установку без изоляции:
  ```powershell
  .\.venv\Scripts\python.exe -m pip install setuptools wheel
  .\.venv\Scripts\python.exe -m pip install -e ".[dev]" --no-build-isolation
  ```
- **`uvicorn` не находит `chess_analyzer`.** Пакет не установлен: выполните `pip install -e .`
  либо запускайте с `--app-dir src`.
- **`/health` показывает `engine.name = "heuristic"`.** Stockfish не найден: проверьте,
  что файл по `STOCKFISH_PATH` существует, и перезапустите сервис — настройки читаются при старте.
