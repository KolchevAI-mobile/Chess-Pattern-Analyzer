## H1. Вертикальный срез MVP

**Цель:** пользователь вводит ник Lichess, получает в приложении «диагноз» по своим последним
партиям. Подробная спецификация — в [MVP.md](MVP.md).

### M1 «Импорт → анализ → диагноз» (⬜, критично для MVP)

Backend:
- [ ] `LichessClient`: `GET /api/games/user/{nick}?max=20&perfType=rapid&clocks=true`, лимит ≤ 1 запрос/с, backoff на 429. Параметр `clocks=true` обязателен, иначе нет времени на ход и не работает `time_trouble`.
- [ ] PostgreSQL в `docker-compose.yml`, миграции Flyway: `users`, `games`, `analyses`, `pattern_hits`.
- [ ] `POST /api/v1/import` (ник, режим, сколько партий) → синхронный ответ на M1; `job_id` — в M2.
- [ ] `GET /api/v1/games` (сводка) и `GET /api/v1/games/{id}` (ошибки постранично) — списки не отдают `payload`.
- [ ] `GET /api/v1/insights` — то, что рисует Android.
- [ ] Кэш разбора по SHA-256 PGN: повторный импорт не запускает Stockfish заново.
- [ ] Передача партии в ML-ядро одним batch-вызовом и сохранение результата с `analysis_version`.

ML:
- [x] Жёсткий потолок глубины `MAX_DEPTH=10` (depth из запроса зажимается в настройках).
- [ ] Batch-приём партий из backend без потери текущего контракта.
- [ ] `analysis_version` и `engine_version` в ответе: понимать, чем посчитан паттерн.
- [ ] Ограничение времени на партию (timeout движка) и понятная деградация.

Android:
- [ ] Сетевой слой (Retrofit или Ktor-клиент) с таймаутом 120 с, DI (Hilt), навигация.
- [ ] Экраны: ввод ника → прогресс импорта → список партий → «Диагноз».

**Критерии готовности:**
1. 20 партий по нику импортируются и анализируются: ≤ 90 с локально, ≤ 5 мин на 1–2 vCPU (depth 10).
2. В приложении виден топ-паттерн, его `severity/confidence` и ≥ 2 доказательства (партия + ход).
3. Повторный импорт тех же партий не пересчитывает анализ (кэш).
4. `docker compose up` поднимает backend + ML + Postgres; health всех трёх — 200.
5. Ошибки внешнего мира (нет ника, лимит Lichess, недоступный движок) показываются человеку понятно.
6. Список партий приходит сводкой, ошибки партии — постранично; Android не парсит мегабайты.

**Риски:** лимиты Lichess API (митигация — backoff и импорт порциями); CPU Stockfish
(митигация — depth ≤ 10, кэш, последовательный анализ в одном воркере).

## H2. Цикл тренировки

**Цель:** превратить диагноз в действие. Паттерн без упражнения остаётся интересным фактом.

### M2 «Асинхронный анализ» (⬜)

- [ ] Очередь задач: Redis + воркер **или** Postgres `SKIP LOCKED` (решение — по итогам M1).
- [ ] Статусы задания (`queued/running/done/failed`), прогресс в приложении, отмена.
- [ ] Метрики воркера: длительность анализа, длина очереди, доля ошибок.
- [ ] Идемпотентность: повторная постановка той же партии не дублирует работу.
- [ ] Lichess OAuth: вход и доступ к приватным партиям (в M1 — только ник и публичные).
- [ ] Импорт до 50 партий за раз: очередь делает это безопасным.

**Критерии:** импорт 50 партий не блокирует UI; виден прогресс; упавшая задача перезапускается.

### M3 «Тренировка и проверка» (⬜)

- [ ] Генератор задач из собственных ошибок: позиция за 1–2 полухода до промаха, «найди лучший ход».
- [ ] Интервальное повторение (SRS) и статистика по темам.
- [ ] Замер «до/после»: cp-loss в целевом паттерне на новых партиях.
- [ ] Экран тренировки + экран прогресса.

**Критерии:** пользователь проходит 10 задач из своих партий; система показывает изменение
метрики целевого паттерна на новых партиях.

## H3. ML: от эвристик к модели

**Цель:** перестать угадывать пороги и начать измерять «сквозной корень» на данных.

### M4 «Паттерны и надлом на данных» (⬜)

- [ ] Датасет: партии пользователей (с согласия) + открытые партии Lichess; разметка паттернов.
- [ ] Формальное определение «надлома»: changepoint-детекция, признаки (время на ход, оценка,
      фаза, история ошибок), а не фиксированное окно.
- [ ] Maia-2 как «человеческая» оценка: различать «объективно плохо» и «трудно для человека».
- [ ] Калибровка «застоя»: полоса 100 Elo / 50 партий, исключение первых ~20 калибровочных.
- [ ] Валидация: precision/recall на отложенной выборке + экспертная разметка 100 партий.

**Критерии:** precision ≥ 0.7 по трём ключевым паттернам; отчёт по калибровке застоя;
решение «какие паттерны показываем пользователю» основано на метриках, а не на интуиции.

## H4. Персонализация, бот и второй источник партий

### M5 «Бот-эксплуататор и план» (⬜)

- [ ] Бот, целенаправленно создающий позиции слабости пользователя (Maia + подстройка).
- [ ] Персональный план тренировок на неделю.
- [ ] Напоминания, стрики, шеринг результата.
- [ ] Монетизация: подписка на глубокий анализ и персональные планы.

**Критерии:** пользователь возвращается ≥ 3 раз/неделю; бот обыгрывает его в целевом паттерне
чаще, чем нейтральный бот того же рейтинга.

### M6 «Chess.com: авторизация и импорт» (⬜, после M5)

Второй источник партий. Делаем после того, как поток Lichess стабилен: интерфейс входа
и модель источников не должны проектироваться «на глазок».

- [ ] Вход через Chess.com (OAuth-flow/токен), привязка внешнего аккаунта к профилю.
- [ ] Импорт партий Chess.com и нормализация в общую модель `games` (поле `source`).
- [ ] Идемпотентность по `(source, external_id)`: повторный импорт не плодит дубликаты.
- [ ] Android: экран входа и выбор основного источника партий.

**Критерии:** пользователь входит через Chess.com и видит свои партии наравне с Lichess;
повторный вход и повторный импорт не создают дубликатов; отзыв доступа отключает источник,
не ломая уже сохранённые партии.

## Риски и допущения

| Риск | Влияние | Что делаем |
|---|---|---|
| Stockfish дорог по CPU на общих серверах | Высокое | depth 10–12, кэш по хэшу PGN, очередь и воркеры (M2), лимит партий на запрос |
| Мало партий → ложные паттерны | Высокое | `confidence` в ответе, минимальные размеры выборки в детекторах, честный текст «данных мало» |
| Лимиты Lichess API | Среднее | backoff, импорт порциями, кэш импортированного |
| Приватность партий | Среднее | только публичные партии, явное согласие на использование для ML, удаление по запросу |
| GPL Stockfish | Низкое | бинарник не коммитим и не распространяем в APK, запускаем как серверный процесс |
| «Надлом» окажется артефактом эвристики | Среднее | держим как сырую метрику, проверяем на данных в M4, не показываем как диагноз до валидации |
