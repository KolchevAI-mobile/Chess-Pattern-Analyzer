Паспорт проекта: Chess Pattern Analyzer
1. Концепция
   Мобильное приложение для начинающих шахматистов, которое анализирует их партии и выявляет сквозные паттерны ошибок (например, «потеря контроля над соперником в выигрышной позиции»).
   Ключевая идея — связать разрозненный анализ партий и тренировки в единый цикл: Диагноз → Выявление корня проблемы → Тренировка → Проверка результата.

2. Проблема и Целевая Аудитория
   ЦА: Шахматисты уровня 800–1400 Elo, которые играют регулярно, но застряли на одном рейтинге.
   Проблема: Существующие сервисы (Chess.com, Lichess) анализируют партии изолированно. Они говорят «зевок», но не связывают ошибки между партиями. Пользователь не видит «сквозной» паттерн и не может целенаправленно его исправить. Человеческие движки (Maia) и объективные (Stockfish) не объединяются в единую экосистему обучения.

3. Ключевые понятия и Метрики
   Сквозной паттерн: Ошибка, которая проявляется в разных фазах игры (эндшпиль, тактика), но имеет один корень (например, слабое чтение доски или потеря концентрации при выигрыше).

«Надлом» (Breaking point): Гипотеза о моменте в партии, после которого качество ходов игрока резко падает. На старте собираем сырые метрики (cp-loss, время на ход, оценка), формальное определение надлома выводится на основе накопленных данных.

Застой: Отсутствие выхода рейтинга за пределы полосы (шириной 100 пунктов) в течение N партий (стартово 50). Калибровочные партии (первые ~20) исключаются.

4. Технологический стек
   Android-клиент: Kotlin (UI, навигация, отображение статистики).

Backend API: Kotlin + Spring Boot (Авторизация JWT, CRUD, управление очередями задач).

ML / Analytics Engine: Python + FastAPI + Stockfish (на старте) + Maia (на следующих этапах).

База данных: PostgreSQL (общая для Kotlin и Python).

Взаимодействие: Kotlin кладет задачу в очередь (RabbitMQ/Redis), Python-воркер забирает, анализирует, пишет результат в БД. Android получает данные через REST API от Kotlin.

5. Архитектура и Пайплайн
   Auth & Sync: Пользователь авторизуется. Kotlin-бэк тянет партии с Lichess API (по нику) и сохраняет в БД.

Analysis (Worker): Python-сервис забирает новые партии, прогоняет через Stockfish, извлекает фичи (фаза, cp-loss, ошибки). Сохраняет результаты в БД.

Insights: Kotlin-бэк агрегирует данные из БД и отдает клиенту статистику по ошибкам.

ML-модель (Следующий шаг): Python-сервис обучается на размеченных данных пользователей (или общих данных), чтобы находить те самые «сквозные паттерны» и «надломы».

Задачи и Бот (Будущее): На основе выявленных паттернов Python-сервис генерирует задачи из партий пользователя или настраивает шахматного бота, который эксплуатирует слабости игрока.
